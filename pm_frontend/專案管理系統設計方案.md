# 專案管理系統設計方案

> 版本：v1.1 | 日期：2026-03-11（已根據需求確認更新）

---

## 一、系統定位

本系統面向**部門內部**的專案全生命週期管理，核心訴求是：

- 讓專案 PM 可以清晰追蹤每個專案從立項到交付的每一個節點
- 讓工程師知道自己今天/本週要做什麼、有沒有超時風險
- 讓主管在不打擾工程師的情況下，隨時瞭解團隊整體工作狀況
- 通過強制審批節點，確保每個關鍵決策都有對應負責人確認

**不做的事（邊界）**：
- 不替代 Git / Jira 做代碼管理或缺陷追蹤
- 不做跨公司、跨組織的協作
- 不做財務成本核算（預算管理可作為後期擴展）
- 工時數據不與外部系統打通，僅系統內記錄

## 二、角色體系

### 2.1 專案角色（Project-scoped）

> ⚠️ 本系統**無産品 PM** 角色。專案 PM 同時承擔需求把控、整體協調、驗收等職責。

| 角色 | 英文標識 | 職責說明 |
|------|---------|---------|
| 專案 PM | project_pm | 需求提出、整體協調、進度把控、立項申請、最終簽收 |
| 系統架構師 | architect | 技術方案制定、技術評審、**開發進度把控** |
| 開發工程師 | developer | 功能開發、進度更新 |
| 測試工程師 | tester | 測試驗證、缺陷回報 |
| 運維工程師 | devops | 環境部署、上線支援 |

**職責分工說明**：
- 專案 PM：負責「做什麼」——需求、優先級、整體里程碑、與業務方溝通
- 系統架構師：負責「怎麼做」——技術拆解、功能任務分配、開發進度驗收

### 2.2 組織角色（Org-scoped）

| 角色 | 說明 |
|------|------|
| 工程師 | 執行層，可查看整個專案所有任務，但只能更新自己負責的任務 |
| 組長 / 技術主管 | 可查看本組所有成員的專案與進度，可審批 |
| 部門主管 | 可查看整個部門的專案、人員工作量、超時統計，有最高審批權 |
| 系統管理員 | 用戶管理、角色分配、層級關係維護 |

### 2.3 層級關係說明

```
部門主管
  └── 技術主管 / 測試主管
        └── 高級工程師 / 架構師
              └── 工程師
```

- 系統通過「人員層級表」維護上下級關係
- 每個人的直屬主管由管理員手動維護（從原 HR 系統遷入）

## 三、專案生命週期

### 3.1 標準流程

```
草稿 ──► 立案審核 ──► 規劃中 ──► 規劃審核 ──► 執行中 ──► 完結審核 ──► 已完結

任意節點可轉：
  ↘ 擱置（暫停，可恢復）
  ↘ 撤回（審核中且未開始審批可撤回）
```

### 3.2 各節點審批規則

| 節點 | 申請人 | 默認審批鏈 | 說明 |
|------|-------|-----------|------|
| **立案審核** | 專案 PM | 專案 PM 的直屬主管 → 部門主管 | 確認專案有必要啟動 |
| **規劃審核** | 專案 PM | 系統架構師的直屬主管 → 部門主管 | 確認技術方案與資源可行 |
| **功能任務完結審核** | 工程師 | 系統架構師（固定，不需到主管） | 架構師確認功能交付達標 |
| **專案完結審核** | 專案 PM | 專案 PM 直屬主管 → 部門主管 | 確認整個專案交付完成 |
| **臨時任務完結審核** | 工程師 | 工程師的直屬主管 | 確認臨時任務完成 |

### 3.3 審批特殊規則

1. **架構師豁免**：若系統架構師本身是主管級或部門主管，規劃審核不再往上傳，本人即是終審
2. **角色合併**：若架構師與專案 PM 是同一人，規劃審核的審批鏈以該人的直屬主管為準（不自審）
3. **部門主管豁免**：部門主管本人發起的申請，跳過默認審批鏈，流程直接通過（或自行審批）
4. **加簽機制**：任意審批節點，審批人可追加指定人員作為額外審批節點
5. **審批結果**：通過 / 拒絕（須填寫原因） / 退回（退回至上一節點重新提交）

## 五、功能模塊設計

### 5.1 專案管理

#### 5.1.1 專案基本信息
- 專案名稱、描述、所屬分組
- 專案 PM（可多人）、系統架構師（可多人）
- 開發工程師、測試工程師、運維工程師（可多人）
- 優先級（低/中/高/緊急）
- 預計開始/結束日期
- 代碼倉庫 URL、相關文檔附件

#### 5.1.2 功能任務（Project Function）

每個專案下由架構師拆分為多個功能任務：

| 字段 | 說明 |
|------|------|
| 功能名稱 | 簡短描述，如「採購模塊後端接口開發」 |
| 所屬分組 | 後端 / 前端 / 測試 / 運維 |
| 負責人 | 可多人，從專案成員中選擇 |
| 優先級 | 低/中/高/緊急 |
| 預計開始/結束日期 | 決定甘特圖位置 |
| 狀態 | 待開始 → 進行中 → 完結審核 → 已完結 |
| 當前進度 | 0–100%，由最新進度記錄決定 |

**進度更新**（工程師填寫）：
- 本次完成度（%）
- 實際耗時（h）
- 工作說明（本次完成了什麼）
- 遺留問題（可選）
- 附件（截圖、文檔等）

#### 5.1.3 里程碑（Milestone）

比功能任務粒度更大的關鍵交付節點，由專案 PM 設定：

| 字段 | 說明 |
|------|------|
| 里程碑名稱 | 如「MVP 上線」「UAT 驗收完成」「正式交付」 |
| 目標日期 | 期望達成日期 |
| 關聯任務 | 關聯哪些功能任務完成視為此里程碑達成 |
| 狀態 | 未達成 / 已達成 / 已逾期 |
| 備注 | 交付物說明 |

達成條件：關聯的所有功能任務均為「已完結」狀態時，里程碑自動標記為達成，並推送通知給相關人員。

#### 5.1.4 甘特圖

- 以時間軸展示所有功能任務的計劃區間與實際進度
- 顏色：灰=未開始、藍=進行中、綠=已完成、紅=超時
- 縮放視圖：日 / 週 / 月
- 過濾：按負責人 / 分組過濾
- 里程碑在甘特圖上顯示為菱形標記 ◆

### 5.2 臨時任務（Temporary Duty）

不屬於任何專案的零散工作事項：
- 工程師自行建立 **或** 主管指派
- 狀態：草稿 → 進行中 → 完結審核 → 已完結
- 審批：完結時提交給直屬主管審批
- 有截止日期提醒，納入主管超時統計
- 進度更新機制與專案功能任務相同

### 5.3 審批中心

統一入口，管理所有需要當前用戶操作的審批事項：

**待審核列表**（分 Tab）：

| Tab | 包含內容 |
|-----|---------|
| 全部 | 所有待審核項 |
| 專案立案 | 新專案立項審批 |
| 規劃方案 | 技術方案審批 |
| 功能完結 | 功能任務完結確認（架構師） |
| 專案完結 | 整個專案完結確認 |
| 臨時任務 | 臨時任務完結確認 |

**操作**：
- 查看申請詳情（附件、說明）
- 通過 / 拒絕（必填原因） / 退回
- 加簽（追加審批人）

**已審核歷史**：可查看自己歷史審批記錄

### 5.4 告警與提醒

#### 5.4.1 截止日期狀態規則

| 狀態 | 條件 | 顯示樣式 |
|------|------|---------|
| 🔴 已超期 | 今日 > 截止日 | 「超期 N 天」紅色加粗 |
| 🔴 緊急臨期 | 截止日 ≤ 3 天 | 「剩 N 天」橙紅色 |
| 🟡 臨期 | 截止日 ≤ 7 天 | 「剩 N 天」橙色 |
| 🟢 正常 | 截止日 > 7 天 | 顯示具體日期綠色 |

在列表頁、詳情頁、首頁均統一使用此規則。

#### 5.4.2 首頁告警欄

工程師首頁顯示：
- 我的超時任務（按超期天數降冪排列）
- 我的臨期任務（7 天內截止，按截止日升冪）
- 待我處理的審批數量

主管首頁額外顯示：
- 下屬超時任務彙整（按工程師分組，顯示各人超時任務數）
- 橫條圖：各工程師當前超時/臨期任務分佈
- 待處理審批總數

#### 5.4.3 通知推送

- **系統內通知**：通知鈴鐺 + 通知列表（已實現框架）
- **外部推送**：調用現有通知接口，系統負責組裝消息內容

推送觸發時機：

| 事件 | 通知對象 |
|------|---------|
| 提交審批申請 | 審批人 |
| 審批通過/拒絕 | 申請人 |
| 任務即將到期（提前 3 天） | 負責工程師 + 直屬主管 |
| 任務已超期 | 負責工程師 + 直屬主管（每天提醒一次） |
| 里程碑達成 | 專案 PM + 架構師 |
| 有人更新了我負責的任務進度 | 架構師（功能任務） / 主管（臨時任務） |

### 5.5 工作量統計（主管視角）

主管可查看下屬在指定時間段內的工作數據：

**查詢維度**：
- 時間範圍：日 / 週 / 月 / 季 / 年 / 自定義
- 人員範圍：全部下屬 / 指定個人

**展示內容**：

| 指標 | 說明 |
|------|------|
| 累計工時 | 該時段內填報的工時加總 |
| 完成任務數 | 狀態變為「已完結」的任務數 |
| 超時任務數 | 實際完成日晚於預計結束日的任務數 |
| 進行中任務數 | 目前仍在進行的任務數 |
| 專案參與數 | 參與的活躍專案數量 |

**圖表**：
- 工時趨勢折線圖（按日/週聚合，可對比多人）
- 任務完成數柱狀圖
- 超時任務橫條圖（按工程師分組，顯示超期天數）
- 專案工時分佈餅圖（個人維度）

## 七、數據模型概覽

```
用戶 (User)
  └── 層級關係 (Hierarchy)：supervisor ↔ subordinate

分組 (ProjectGroup)
  └── 專案 (Project)
        ├── 成員分配 (ProjectMember)：工程師/架構師/PM 等
        ├── 功能任務 (ProjectFunction)
        │    ├── 負責工程師 (Function Allocation)
        │    ├── 進度記錄 (ProgressRecord)：完成%/工時/說明/附件
        │    └── 審批申請 (ApplyRecord) → 審批節點 (ApprovalNode)
        ├── 里程碑 (Milestone)
        │    └── 關聯功能任務 (MilestoneFunction)
        └── 審批申請 (ApplyRecord) → 審批節點 (ApprovalNode)

臨時任務 (TemporaryDuty)
  ├── 負責人 (Responsible)
  ├── 進度記錄 (DutyProgressRecord)
  └── 審批申請 (ApplyRecord) → 審批節點 (ApprovalNode)

審批節點 (ApprovalNode)
  ├── 審批人 (approver_work_no)
  ├── 審批順序 (order)
  ├── 狀態 (pending/approved/rejected/returned)
  ├── 審批意見 (comment)
  └── 是否加簽 (is_countersign)
```

## 八、開發優先級建議

### Phase 1 — 核心流程完善（現有功能補強）
1. **任務視圖切換**：功能任務列表 + 臨時任務列表加入「全部/我的」Tab
2. **審批流程完整化**：多級審批節點展示、加簽、退回操作
3. **首頁告警欄**：超時/臨期任務清單，按緊急程度排序
4. **通知推送組裝**：對接現有通知接口，實現關鍵事件推送

### Phase 2 — 管理視角
5. **甘特圖**：專案詳情頁，依賴 dhtmlx-gantt 或 frappe-gantt
6. **工作量統計頁**：主管工時圖表 + 超時分析
7. **下屬進度查看**：主管可按工程師過濾任務列表

### Phase 3 — 體驗完善
8. **里程碑管理**：專案詳情新增 Milestone Tab
9. **報表導出**：Excel / PDF 格式
10. **移動端適配**：響應式佈局優化
